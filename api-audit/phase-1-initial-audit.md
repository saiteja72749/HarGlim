# Phase 1 initial audit

The workspace contains the Next.js 16.4.6 App Router frontend. The supplied OpenAPI and backend handover identify an external Express/MongoDB API. Backend source, database configuration, and an authorized transactional staging environment are unavailable. Existing uncommitted work includes storefront, SEO, responsive layout, and QA changes.

| Area | Source evidence and root cause | API boundary | Risk and proposed change |
| --- | --- | --- | --- |
| Shared layout | `components/layout/navbar.tsx` drives a scroll progress animation, uses a separate scroll listener, and renders a fixed header. `components/layout/main-container.tsx` duplicates route exclusions and reserves a measured offset. `app/dashboard/layout.tsx` positions its sidebar at a hard-coded offset and keeps the off-screen mobile links in the DOM. | Zustand session/cart and CMS announcements | Medium. Use a sticky header in normal flow and an accessible reader navigation drawer. Retain supported role links. |
| Public navigation and categories | The header, footer, and home link to a separate category route. `app/books/page.tsx` already accepts category IDs and slugs and loads the catalog for filtering. Footer links use unsupported sort values. `app/sitemap.ts` indexes category routes. | Public category and book reads | Medium. Redirect legacy routes, link to the catalog directly, and preserve selected category context. |
| Home, authors, publish, about | `app/page.tsx` conditionally renders CMS FAQ and other content. `app/authors/page.tsx` already supports searching and sorting by count or name, but inserts placeholder biographies. `app/publish/page.tsx` and `app/about/page.tsx` use existing CMS data and publishing packages. Visual reports alone cannot establish current layout defects. | `/content`, `/books`, `/authors`, `/publish-packages`, `/stats/public` | Low to medium. Refine evidence-backed gaps and keep CMS copy and package identifiers intact. |
| Contact and metadata | `app/contact/page.tsx` has a disabled pending button but lacks a synchronous submission guard and treats any successful HTTP response as acceptance. The source contains the official logo and no favicon route. | `POST /contact` is absent from the supplied OpenAPI. The CMS owns contact details. | Medium. Keep the existing payload and check explicit failure envelopes. Derive the favicon from the official artwork. |
| Book and cart | `components/books/book-detail-view.tsx` renders descriptions as plain paragraphs. `store/cart-store.ts` stores cart lines locally and totals exclude unconfirmed shipping. The cart and detail already have quantity controls and responsive imagery. | Books, related titles, reviews, and purchase eligibility reads | Medium. Render a safe Markdown subset and preserve stock and pricing rules. |
| Checkout and UPI | `app/checkout/checkout/page.tsx` saves addresses by default, can overwrite the list after a failed read, keeps a confirmed order in transient modal state, and clears the cart only after UTR submission. `app/dashboard/orders/page.tsx` provides the existing resume flow and shows a 12-digit placeholder despite a 6–64-character validator. | Saved addresses, `POST /orders`, `PUT /orders/{id}/verify-payment`, owner-scoped payment reads. No documented pre-order quote or idempotency key. | High. Prevent duplicate requests, retain the confirmed order after dismissal, require explicit address-save intent, and present backend amounts before payment. |
| Reader account | The overview, orders, wishlist, library, history, profile and application routes exist. `app/dashboard/library/page.tsx` offers print formats in a digital library. `app/dashboard/profile/page.tsx` opens fields in edit mode. `app/dashboard/become-author/page.tsx` treats all status-read errors as an invitation to apply. | Owner-scoped reader resources, saved addresses, `/users/me/author-application`, `/author-applications` | Medium to high. Tighten view/edit and submission states while keeping existing auth and ownership. |

Existing Vitest coverage includes cart, auth, API errors, saved addresses, catalog and status normalization. Playwright covers public navigation, select mobile layouts, live public endpoints and existing author reads. Missing coverage includes the full viewport matrix, keyboard reader navigation, retry and repeat-click order creation, UTR transitions, contact delivery, and authenticated reader writes. Earlier run results do not certify the current worktree. The crawl of the public home showed the legacy Categories link. Current local layout and deployed SEO responses require separate verification.
